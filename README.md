# BOBBLE RUN bot (MVP)

Локальный бот для https://unboxbobble.com/run. Он смотрит на экран, понимает, что происходит, и нажимает клавиши, как живой игрок. Никаких записанных последовательностей: каждое решение принимается по текущему кадру.

```
screenshot (mss) → vision (OpenCV) → GameState → decision (rules) → keyboard (pynput) → …
```

## Что известно об игре

| | |
|---|---|
| Жанр | раннер с тремя дорожками, 8 локаций, скорость растёт с уровнем |
| Управление | `←/→` или `A/D`: дорожка, `↑`/`W`/`Space`: прыжок, `↓`/`S`: подкат, `Esc`/`P`: пауза |
| Рестарт | на экранах Play / Resume / Run again кнопка в фокусе, её нажимает `Enter` |
| Важно | **если окно браузера теряет фокус, игра сама встаёт на паузу**. Поэтому окно отладки сделано «некликабельным» и не забирает фокус |

## Как бот видит игру

* **Геометрия дорожек** рассчитывается из параметров камеры игры (FOV 62°, камера следует за игроком по X и по высоте прыжка). Поэтому разметка работает на любой локации и при любом размере окна.
* **Игрок** определяется по зелёной футболке и тёмной кепке над ней. По координате на экране вычисляются его дорожка и высота прыжка.
* **Препятствия**: для каждой строки дороги строится модель цвета (медиана строки плюс временная память). Пиксели, сильно отличающиеся от дороги, собираются в объекты. Нижний край объекта даёт расстояние до него, ширина даёт занятые дорожки. Трекинг между кадрами даёт скорость и время до столкновения (TTC).
* **Монеты**: золотые пятна на дороге.
* **Экран**: если есть кнопка паузы в HUD, идёт игра; бумажный чек означает Game Over; карточка PAUSED означает паузу.

Проверено на скриншотах всех 8 локаций (фабрика, мост, крыши, аукцион, аркада, Луна…).

## Установка (Windows + Chrome)

Нужен Python 3.11+.

```powershell
cd путь\к\репозиторию
py -3.11 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## Запуск

1. Откройте игру в Chrome. Окно лучше развернуть, масштаб страницы 100%.
2. Выберите область игры. Выделяйте **только саму страницу**, без вкладок и адресной строки:
   ```powershell
   python -m bobble_bot.select_region
   ```
   Область сохранится в `config.json`. Окно отладки встанет справа от игры, если там есть место, иначе под ней.
3. **Режим наблюдения** (бот ничего не нажимает, только показывает, что видит):
   ```powershell
   python -m bobble_bot
   ```
   Кликните один раз в игру, чтобы фокус был на Chrome, и начните играть сами. В окне `bot debug overlay` должно быть видно:
   - голубые линии лежат на краях и разметке дороги;
   - зелёная рамка на персонаже, подпись `lane -1/0/+1`, `ground/AIR`;
   - красные рамки на препятствиях с расстоянием `z` и временем до удара `t`;
   - цветные полосы по дорожкам: зелёная — свободно, жёлтая — близко, красная — опасно.

   `F10` отправляет одно тестовое действие (прыжок). Так проверяется, что игра принимает нажатия.
4. **Бот играет сам**:
   ```powershell
   python -m bobble_bot --play
   ```
   Можно сразу открыть игру: `python -m bobble_bot --play --open`.

### Горячие клавиши

| Клавиша | Действие |
|---|---|
| `F8` | аварийная остановка (бот завершается, все клавиши отпускаются) |
| `F9` | пауза / продолжить (индикатор `BOT ACTIVE` / `BOT PAUSED`) |
| `F10` | тестовое действие (прыжок) |
| `Esc` в окне отладки | выход |

### Безопасность

* Клавиши отправляются **только когда активное окно содержит в заголовке `BOBBLE`** (`window_title_contains` в `config.json`). Если вы переключились в другое окно, бот ничего туда не нажмёт.
* Между действиями есть минимальный интервал, бот не спамит клавишами.
* Все действия пишутся в `logs/actions-*.jsonl`, общий лог в `logs/bot.log`.
* При каждой смерти последние 4 секунды отладочного видео сохраняются в `logs/debug/<время>-death/` (`last_seconds.mp4` и `last_frame.png`).

### Другие флаги

| Флаг | |
|---|---|
| `--dry-run` | ничего не нажимать, только логировать решения |
| `--record` | сохранять кадры, состояние и действия в `dataset/` для будущего обучения. Если бот на паузе (F9), записываются **ваши** нажатия: так собирается датасет для imitation learning |
| `--engine module:Class` | подключить свой движок решений (ML/RL) вместо правил |
| `--select` | заново выбрать область игры |
| `-v` | подробный лог |

## Если разметка не совпадает

* Убедитесь, что выделена ровно страница игры: без адресной строки и без полей рабочего стола.
* Масштаб страницы в Chrome 100% (`Ctrl+0`).
* Если голубые линии стабильно выше или ниже дороги, поправьте `y_offset_px` в `config.json` (пиксели в обработанном кадре шириной 640, например `-5` или `8`).
* Слишком много ложных красных рамок: увеличьте `dev_threshold` (по умолчанию 16).

Скриншоты можно проверить без игры: `python tools/offline_vision.py "shots/*.png" --out debug_offline`.

## Структура

```
bobble_bot/
  __main__.py      главный цикл, горячие клавиши, оверлей
  capture.py       захват экрана (mss)
  geometry.py      модель камеры игры: мир ↔ экран
  vision.py        игрок, препятствия, монеты, тип экрана → GameState
  state.py         структуры GameState / Player / Obj
  decision.py      RuleBasedEngine + интерфейс для ML-движка
  controller.py    InputController (pynput), DryRun, проверка фокуса окна
  overlay.py       отладочный оверлей
  recorder.py      лог действий, видео при смерти, датасет
  select_region.py выбор области игры
  winutil.py       DPI-awareness, «некликабельное» окно отладки
tools/offline_vision.py  проверка зрения на скриншотах
```

## Известные ограничения MVP (следующие итерации)

* Пока не различаются типы препятствий: что перепрыгнуть (`low`), под чем проехать (`high`), где яма (`gap`), где рампа. Если свободной дорожки нет, бот прыгает. Подкат и классификация препятствий — следующий шаг, нужны записи игры (`--record`).
* Если игрок перекрыт препятствием или эффектом, бот кратко использует последнюю известную позицию.
* Задержки ввода и захвата на вашей машине нужно измерить: смотрите `latency` в оверлее и при необходимости подстройте `react_time` и `jump_time`.
